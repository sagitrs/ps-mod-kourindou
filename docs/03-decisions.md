## 1. 玩法与显示

| ID | 待决定事项 | 推荐方向（非定案） | 阻断的交付 |
|---|---|---|---|
| D01 | 下/中/上城区显示名是否改成魔法森林/人里/雾之湖 | 原内部身份不变；若改名只改指定显示面 | 地区命名、对应文本验收 |
| D02 | 好感初值、增长/下降来源、单次值、日上限；低于100后已解锁功能是否仍可用 | 新角色从0开始；先以真实成功交易增长、设日上限、不加自然衰减；数值按目标养成天数再定，不凭空加入赠礼系统 | 好感规则与节奏验收 |
| D03 | 三人的具体夜间帮助、价格、支付时机、次数与冷却 | 使用原系统能安全支持的效果；每人每晚最多一次、不消耗好感可作候选。供货、鉴定、次日经营加成仅为选项，不是已定技能 | 三人夜间功能完整交付 |
| D04 | 地区客流倍率、加权是否包含原NPC、基础三人出现率 | 至少增加对应新增角色权重，保持其他NPC可出现；不宣称加权后原概率完全不变 | 抽样与平衡验收 |
| D05 | 搬迁生效时刻、费用、声望下降后的资格、能否回原背景 | 夜间选择、次日生效、可回原背景；已搬入不因下降强制搬走可作候选 | 搬迁状态机 |
| D06 | 每日模式何时生效、每天次数、是否增加总客流、开门不足/剧情日等例外 | 次日生效、每人每日一次，正常营业日确定性安排；不抢剧情。不把未到场记录为完成，不用暗中轮换代替保底 | 每日来访可靠性 |
| D07 | 买店前的好感溢出是否储存、买店后如何继续 | 买店前截断100且不暗存溢出，买店后从已有值继续，不凭空送好感 | 上限与买店迁移 |
| D08 | 多角色恋爱/婚姻是否允许、是否告白/求婚、CG是否永久/可回看/跨档 | 各角色独立，不自动加排他与嫉妒；本局永久解锁并可回看，跨档收藏先不做 | 关系状态、CG流程与文本 |
| D09 | 旧档支持与主角/店名处理 | 兼容旧档，识别已买店状态；新局默认香霖堂，旧档不静默改名，玩家后续改名不覆盖 | 新旧档、命名与启用说明 |

原派系100、个人100、150、200是已确定门槛，不属于可由实现者自行调低的平衡值。上述待定项若导致目标无法满足，应交用户决定，不能将按钮隐藏或占位内容称为完成。

## 3. 最终目标后续再定

全NPC随机替换的角色池、随机时机、去重/分池、剧情功能映射、旧档升级，以及赛博内容替换清单，属于后续目标。**这些问题不阻断V1三人的固定设计。**

建议先从D10的版本与测试入口做适配可行性验证；D02、D03、D06决定主要可玩循环，应在对应功能实现前明确。D01/D04/D05影响地区模块，D07/D08/D09影响状态与存档，D11决定后续如何入仓。

## 4. 决定如何生效

每次确认记录“ID、选择、提出者确认来源、适用版本、受影响Issue及日期”。没有确认来源就仍然是候选。本次仓库与操作范围已记录在主Issue；玩法选择后续在真实Issue/PR中逐项补齐，不以文档入仓自动批准推荐项。

改动V1范围必须明确说明增减，不把最终目标的全量改造悄悄追加到首版，也不把原本保留的好感/夜间/CG/来访功能悄悄推迟到终版。

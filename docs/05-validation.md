# 验收与验证方案

[需求](01-product-design.md) · [决策](03-decisions.md) · [任务分解](../planning/README.md)

**当前全部产品验收项未执行。** 下面是将来的方法与预期，不是通过记录；本次整理中进行的Markdown/依赖核对不计为游戏测试。

## 1. 三层证据

1. **纯规则测试**：上限/阈值、概率权重、权限、日程去重、状态迁移。可在Linux执行，但不能证明游戏事件真实接入。
2. **集成构建与包检查**：真实目标程序集编译、依赖/manifest/资源检查、游戏实际扫描器。缺游戏引用应报告输入不足，不能用模拟类型生成假兼容结论。
3. **真实游戏验收**：目标正式版中加载、操作、关闭重启、保存/读档、禁用/原版读档、剧情兼容与性能。使用测试档，不覆盖日常档。

每份结果至少记录源码/包摘要、游戏构建、测试环境、前置存档、操作步骤、实际观察、预期及状态。区分产品失败、环境无法执行、尚未覆盖；不把跳过计为通过。重复运行不重复累加成新覆盖。

## 2. V1验收矩阵

| ID | 需求 | 场景与必须观察到的结果 | 重要反例/边界 |
|---|---|---|---|
| AC01 | R10 | 用真实引用构建、扫描、启用并重启，在目标游戏显示有效状态 | 缺DLL、错误版本、扫描拒绝不能报兼容；纯逻辑通过不替代 |
| AC02 | R02 | 三人分别在指定城区来源中作为独立新增角色出现；原NPC和关键剧情仍可运行 | 不允许删除原NPC来腾名字/头像；不新增第四位东方人物 |
| AC03 | R02/R04/R09 | 同一人买卖身份切换、再访、读档后好感归属一致，三人互不串线 | 同头像/同名字不应成为ID；Mod来源标记不代唯一角色身份 |
| AC04 | R01 | 新局主角/初始店名符合要求；后续改名及旧档按D09处理 | 不能每次读档把玩家店名强制覆盖；不全局重写原NPC对白 |
| AC05 | R04 | 按D02真实事件增长，进度条与存档一致；买店前99→100及超过上限正确 | 取消/失败交易不冒成功；日上限/重入按确认规则执行 |
| AC06 | R06 | 未买店、刚买店、原已买店旧档分别得到正确上限 | 现金足够/房租零不是买店；跨上限与溢出按D07，买店不送分 |

| AC09 | R07 | 149/150、199/200及一次跨过两档均正确解锁并有实际CG | 缺图不是完成；按D08处理首次播放、确认、回看及关系路线 |
| AC10 | R03 | 城区声望99不可搬，100可搬；三个背景正确显示并可读档恢复 | 不用角色好感代派系好感；库存、房产、剧情、柜台不被重建 |
| AC11 | R03 | 地区倍率实际进入客流消费者；固定输入/种子可复核抽样规则 | 去掉加权调用时测试应失败；不只验证配置存在或按钮显示 |
| AC12 | R08 | 三模式互斥，三人可分别选择；目标身份真实到柜台 | 提高权重不算每日保底；入队不算到场，到场不算成交 |
| AC13 | R03/R08 | 自然与保底去重，一天多次开门/重载不重复；次日按D06更新 | 早关店/剧情日等按已批准例外；不悄悄轮换/限额或抢剧情 |
| AC14 | R01—R08 | 角色面板、夜间入口、背景、CG中文可读且不挡本体交互 | 长文字、不同分辨率、外出返回、切场景、重复打开关闭 |
| AC15 | R09 | 至少两个存档槽、新局、未买店/已买店旧档相互隔离 | 坏数据、未知schema、缺包保留原数据并提示，不静默清零 |
| AC16 | R09 | 保存→退出→禁用Mod→原版读档可用；再启用按约定恢复 | 包含队列中角色、Mod头像键和临时效果的存档也要覆盖 |
| AC17 | R02/R10 | 12项基础美术和三人文本完整、资源键有效、权利清单可核 | 占位、缺图、重复ID、越界路径/错误格式不得冒正式内容 |
| AC18 | R09/R10 | 版本不匹配、缺资源/依赖及同类Mod冲突有明确可见行为 | 不在适配失效后继续写坏状态，不宣称未测Mod组合兼容 |
| AC19 | R10 | 在D13固定场景与预算下测帧时、加载、内存/包体，保留同机基线 | 多次看CG/切场景无不可接受增长；不能以服务器容量代玩家验收 |
| AC20 | R10 | 分发包只含获准自有代码/资源与必要说明；能力声明和实际行为一致 | 不夹游戏DLL、游戏素材、真实存档、凭据；不联网或绕过扫描 |

候选验证工作量：三人分别跑一轮完整门槛流程、三人混合来访模式连续多个游戏日、20次CG面板开关和场景往返。具体天数/性能阈值由D13在执行前锁定，不在看到结果后降标准。

## 3. 测试资产随实现交付

- 每个功能任务同时交可运行测试、真实游戏复现步骤与需要的合法测试夹具；最终集成任务不是替前面补全部测试。
- 接入目标仓实际测试发现/CI入口，不能把未运行的文件计为覆盖。
- 关键规则保留至少相称反例：取消100门槛、跳过买店判断、去掉去重/权重消费者、将入队当到场等错误必须能被相关测试发现。
- 模拟游戏适配器可测纯规则，但报告中明确它不能证明实际Unity对象、钩子时序或存档载入。
- 游戏截图/视频应脱敏；游戏引用、原生存档等受限制物料留在受控位置，不为方便CI泄漏到公开产物。

## 4. 交付边界

V1验收覆盖上述已定需求及已批准决策。关键决策仍待定、资源未授权、游戏内关键项未测时，状态只能是原型/候选，不能宣布完整V1。

全NPC随机替换和赛博清理另有最终目标验收；既不因为V1只含三人判其失败，也不因为V1通过就关闭长期总目标。代码合入、玩家包交付、公开发布分别留记录。
